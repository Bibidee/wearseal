# Security

URLs require HTTPS and bounded lengths. Evidence is hostile data and prompts prohibit following embedded instructions. Owner and renter zero addresses are rejected, return submission is deadline-bound, and expiry cannot overwrite a decided or settled agreement. Policy is immutable after renter acceptance. Owner payouts are derived from stored Agreement state, never caller input. Settlement uses an explicit verdict-to-basis-points mapping and exact-once state guards; the renter remainder is computed after integer division.

The final payout architecture does not use `emit_transfer`. GenLayer is the adjudication and accounting layer only. A server-side relay reads Agreement and Vault state directly and derives recipients and amounts; client-supplied payout fields are rejected. The Base escrow requires a relayer registration containing the authoritative renter and exact deposit before funding, rejects duplicate funding, has no administrator withdrawal path, and accepts one exact full-collateral allocation. Each recipient calls the escrow's pull-style `claim`. The escrow zeroes claimable state before the synchronous EVM call; if the call fails, the whole transaction reverts and the claim remains retryable. A configured Studionet attestor records funding and claims only after the server verifies finalized Base receipts, calldata, senders, payout events and amounts. Claim acknowledgements use GenLayer's supported leader-only mode because the receipt has already been independently verified and the method is guarded by the attestor address; this is an operator trust boundary, and the cross-chain path is not claimed to be fully trustless.

Protocol references: [Value Transfers](https://docs.genlayer.com/developers/intelligent-contracts/features/value-transfers), [Messages](https://docs.genlayer.com/developers/intelligent-contracts/features/messages), and [Querying a Transaction](https://docs.genlayer.com/developers/decentralized-applications/querying-a-transaction).
